# 다빈치스쿨 홈페이지 + 서논술형 플랫폼 설계

작성일: 2026-09-18
상태: 승인 대기 (대표님 검토 후 구현 계획 작성)
발표 목표일: 2026-10-18 (가맹원 원장님 대상 리뉴얼 시연)

---

## 1. 배경과 목표

다빈치스쿨은 탐구보고서 수업을 전국 약 40개 가맹원에 공급하는 본사다. 1달 뒤 리뉴얼된 모습을 원장님들께 시연해야 한다.

다빈치스쿨의 사업은 4개:
1. 서논술형 수업 (신규)
2. 대입 컨설팅
3. 자기주도 학습관 (다빈치랩)
4. 탐구보고서 (기존 수업)

이번 프로젝트의 범위는 **메인 홈페이지 + 서논술형 플랫폼**이다. 탐구보고서·컨설팅·다빈치랩은 소개 페이지만 만든다.

### 발표의 성격
원장님들 앞에서 대표님이 **시연**한다. 실제 사용 개시는 발표 후 몇 주 더 다듬은 뒤다. (실사용 개시가 아니므로 결제·전체 과목 투입은 범위 밖.)

### 성공 기준
- 원장님이 로그인해서 학생을 등록하고, 본사 문항을 배정하고, 학생이 답안을 내면 AI 채점·피드백이 30초 안에 뜬다.
- 관리자가 대주제 하나로 5과목 문항 세트를 파이프라인으로 만들어 게시할 수 있다.
- 공개 홈페이지가 밝은 파스텔톤으로 4개 사업을 소개하고 가맹문의를 받는다.

## 2. 사용자와 역할

| 역할 | 누구 | 소속 |
|---|---|---|
| 방문자 | 학부모, 가맹 희망자, 누구나 | 없음 (로그인 없음) |
| 관리자 | 대표님 + 관리자 1명 (총 2명) | 본사 |
| 원장(교사) | 가맹원 원장님 | 원 1곳 |
| 학생 | 원장님이 발급한 계정 | 원 1곳 |

권한 원칙:
- 원장은 **자기 원 학생만** 본다. 다른 원 데이터는 URL을 알아도 접근 불가.
- 학생은 **자기 과제와 결과만** 본다.
- 관리자는 전체를 본다.
- 이 규칙은 화면이 아니라 **DB 행 단위 보안(Supabase RLS)** 으로 강제한다.

## 3. 화면 구성

### 3.1 공개 (로그인 없음)
- `/` 메인: 상단 로고·메뉴, 우상단 **[가맹문의]** 버튼 + **[로그인]**. 다빈치스쿨 한 줄 소개, 4개 사업 카드, "왜 다빈치인가", 가맹원 현황(전국 N개), 문의 유도.
- `/programs/inquiry` 탐구보고서 소개
- `/programs/essay` 서논술형 소개 (수업 흐름, AI 채점 예시)
- `/programs/consulting`, `/programs/lab` 준비 중 페이지
- `/franchise` 가맹 안내 + 문의 폼 (이름·연락처·지역·메시지 → 관리자 이메일 알림 + 관리자 접수함)
- `/login` 단일 로그인. 역할에 따라 `/admin`, `/teacher`, `/student`로 이동.

### 3.2 관리자 `/admin`
- 대시보드: 원 수, 학생 수, 이번 달 채점 건수, AI 비용 추정, 채점 대기/실패 건, 재채점 요청 집계(문항별)
- 가맹원 관리: 원 등록, 원장 계정 발급, 원별 학생 정원·월 AI 채점 상한
- 문항 제작소: 대주제 → 과목별 문항 세트 파이프라인 (§5)
- 문항 목록: 대주제/학교급/과목/학년별, 상태(초안/검토 중/게시/내림)
- 가맹문의 접수함: 신규/연락함/완료
- 공지 작성, 자료실 업로드
- 홈페이지 문구 편집: 메인 소개문·슬로건·가맹원 수·대표 사진 (우선순위 낮음)

### 3.3 원장 `/teacher`
- 학생 관리: 추가(이름·학교급·학년), 아이디·초기 비밀번호 자동 발급(초기 비밀번호는 1회만 표시), 비밀번호 초기화, 퇴원 처리
- 문항 찾기: **대주제로 찾기**(STEAM 전과목) / **과목으로 찾기**(단과). 학교급·과목·학년 필터. 게시된 문항은 원 구분 없이 **전체 공개**.
- 문항 미리보기: 문항·루브릭·예시답안·교사용 지침서·차시 설계 열람
- 배정: 학생 여러 명 선택 → 마감일 → 재도전 허용 여부(기본 1회 허용)
- 결과 보기: 학생별 답안, AI 등급, 피드백, 원장 코멘트 추가, [재채점 요청]
- 대리 입력: 종이 답안을 학생 대신 입력 → 동일 채점, "원장 입력" 표시
- 자료실 다운로드, 공지 열람

### 3.4 학생 `/student`
- 내 과제 목록: 미제출 / 제출(채점 중) / 채점 완료
- 과제 화면: 문항 읽기 → 답안 입력(임시저장) → 제출
- 결과 화면: 종합 등급, 요소별 등급+근거, 잘한 점, 보완할 점, 원장 코멘트, 재도전 버튼(허용 시)
- 글자 크기 공개 화면보다 크게

### 3.5 디자인
- 흰 바탕, **민트 주색**, **레몬 강조색**(버튼·배지), **연보라 보조색**
- 둥근 모서리, 넉넉한 여백, 깔끔함
- 1주차에 시안 2~3개를 만들어 대표님이 선택

## 4. 데이터 구조

### 4.1 사람과 조직
- **academies (가맹원)**: 이름, 코드(예 `seoul01`), 지역, 원장 연락처, 상태(운영/휴원), 학생 정원, 월 AI 채점 상한(건수)
- **profiles (계정 부가정보)**: Supabase auth 사용자와 1:1. 역할(admin/teacher/student), 소속 academy(관리자는 null), 이름
- **students**: profile과 1:1. 학교급(초/중/고), 학년, 재원 여부, 학생 아이디(`원코드-번호`, 예 `seoul01-023`)

### 4.2 교육과정
- **standards (성취기준)**: 학교급, 과목(국어/영어/수학/과학/사회/한국사), 학년군, 영역, 코드(예 `[9국03-04]`), 원문. **읽기 전용**. 2022 개정 교육과정 별책 PDF에서 추출.

### 4.3 문항
- **themes (대주제)**: 제목, 소개문, 대상 학교급·학년, 상태(초안/게시). 예: "자연보호를 위해 학교 축제에서 일회용품 사용 줄이기 (중2)"
- **item_sets (문항 세트)**: theme 소속, 과목, 학교급·학년, 상태(초안/검토 중/게시/내림), 버전 번호, 생성 로그(Claude 반복 회차·검토 요약). 내용:
  - 선택한 standards (다대다)
  - 재구성: 핵심 기능어, 수행방법, 산출물, 재구성 문장
  - 핵심 질문
  - 차시 설계 (차시별 활동)
  - 교사용 지침서
  - 서논술형 문항 (지문·질문·조건·분량)
  - 루브릭 (평가요소 × 상/중/하 기준)
  - 예시답안 상/중/하
- 게시 후 수정은 **새 버전**. 이미 배정된 과제는 배정 당시 버전을 유지한다.

### 4.4 수업 운영
- **assignments (배정)**: item_set(버전 고정), academy, 학생, 마감일, 재도전 허용 여부, 상태(진행/마감)
- **submissions (답안)**: assignment당 N건(재도전 시 2건). 본문, 임시저장 시각, 제출 시각, 입력자(학생/원장), 회차
- **gradings (채점 결과)**: submission당 1건. 요소별 등급+근거 인용, 종합 등급, 잘한 점[], 보완할 점[], 모델명, 입력/출력 토큰, 상태(완료/대기/실패), 원장 코멘트, 재채점 요청 여부

### 4.5 운영
- **franchise_inquiries**: 이름, 연락처, 지역, 내용, 접수 시각, 상태(신규/연락함/완료)
- **notices**: 제목, 본문, 대상(전체/원장), 게시일
- **resources (자료실)**: 파일명, 설명, 대상, 업로드일, 저장소 경로
- **site_settings**: 키-값 (메인 소개문, 슬로건, 가맹원 수 등)
- **student_count_snapshots**: 매월 1일 원별 재원 학생 수 (향후 과금 근거)

## 5. 문항 제작 파이프라인 (관리자)

문항은 **본사가 만들고** 원장은 고르고 배정만 한다. 각 단계는 독립된 Claude 호출이며 결과가 저장되어 중단 후 재개 가능. 각 단계에서 관리자가 수정할 수 있고 [다음]을 누르기 전까지 확정되지 않는다.

**STEAM 원칙**: 대주제 하나를 여러 과목이 나눠 맡는다. 예: "학교 축제 일회용품 줄이기" → 국어(근거 들어 주장하는 글) / 수학(사용량 자료 정리·그래프) / 영어(설문조사 결과 발표) / 사회(SDGs 탐구보고서) / 과학(탄소화합물·플라스틱).

| 단계 | 관리자 | Claude |
|---|---|---|
| 0. 대주제 | 대주제·대상 학년·참여 과목 입력 | 소개문 + 과목별 연결 아이디어 한 줄씩 제안 |
| 1. 성취기준 선택 | 과목별 최종 선택 | 대주제에 맞는 성취기준 추천(체크) |
| 2. 재구성 | 핵심 기능어·수행방법·산출물 선택, 문장 수정 | 원문에서 기능어 추출, 수행방법/산출물 후보, 재구성 문장 작성 |
| 3. 핵심 질문 | 선택/수정 | 후보 2~3개 |
| 4. 차시·지침서 | 차시 수 결정(기본 3~4), 수정 | 차시별 활동 흐름, 교사용 지침서(도입·전개·정리, 발문, 유의점, 준비물) |
| 5. 문항·루브릭·예시답안 | 최종본 검토·수정 | **자동 반복 구간** (아래) |
| 6. 게시 | [게시] | — |

**5단계 자동 반복** (관리자에게 중간 과정을 보여주지 않음):
1. 문항 초안 → 2. 루브릭 초안(평가요소 3~4개 × 상/중/하) → 3. 예시답안 상/중/하
4. **검토자 호출**(별도 Claude 호출): 성취기준 이탈 여부, 루브릭으로 상/중/하 예시답안이 실제 구분되는지, 학년 수준, 조건의 모호성
5. 문제 있으면 1로 (최대 3회) → 6. 통과 시 최종본 + 검토 요약 표시

**"기본값으로 진행"** 버튼: 과목 하나를 Claude 추천값으로 자동 통과시켜 시간 절약.

**프롬프트 재료**: 서논술형 공통작성양식, 과목별 서·논술형 평가 실천하기 자료집, 루브릭 샘플, 「성취기준에서 문항까지」. 단계별 프롬프트에 녹여 다빈치 스타일을 일관되게 유지.

**모델**: 0~4단계 Sonnet, 5단계(반복·검토) Opus.

**시연용 목표**: 대주제 2개 × 학년 2개(중2 우선, 초5 또는 고1) × 5과목 = 문항 세트 최대 20개. 일정에 따라 축소 가능.

## 6. AI 채점·피드백

### 6.1 흐름
학생 [제출] → submission 저장, grading "대기" 생성 → 서버에서 Claude(Sonnet) 호출 → 결과 저장 → 학생·원장 화면 반영. 목표 10~30초.

### 6.2 입력
문항, 루브릭 전체, 예시답안 상/중/하, 학생 답안, 학생 학년.

### 6.3 채점 원칙
- 루브릭 **요소별** 등급 → 종합 등급 순서.
- 등급마다 **답안에서 근거 문장 인용**.
- 잘한 점 / 보완할 점 분리. 보완할 점은 **루브릭의 한 단계 위 기준**에서 도출("다음 등급으로 가려면").
- 학생에게 존댓말, 학년 어휘.
- 응답은 JSON 고정 형식. 온도 낮게.

### 6.4 안정성
- 형식 오류 시 자동 재시도 1회. 재실패 → "대기" + 관리자 대시보드 표시 + [다시 채점].
- 답안 50자 미만 또는 문항과 무관 → 채점 대신 "다시 써 보세요" 안내 (비용 절감).

### 6.5 원장 권한
- AI 등급 **수정 불가**, 코멘트만 추가. (본사 기준 일관성 유지)
- [재채점 요청] → 관리자 검토. 문항별 재채점 요청 수를 대시보드에 집계 (문항 품질 신호).

### 6.6 재도전
배정 시 원장이 허용 여부 결정(기본 1회 허용). 재도전 답안은 새 채점, 이전 결과 보존 → 향상도 확인.

### 6.7 비용 관리
- grading마다 토큰 기록 → 원별·월별 합계, 원화 환산 표시.
- 원별 월 상한 도달 시 제출은 되고 채점은 "대기". 원장 화면에 안내. 관리자가 상한 상향 시 대기분 자동 처리.
