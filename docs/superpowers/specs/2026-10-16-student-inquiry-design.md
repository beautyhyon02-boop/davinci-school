# 학생이 시작하는 교과융합탐구보고서 설계

- 결정일: 2026-10-16 (본사 사무실, 설명 뒤 선택)
- 바탕: `docs/superpowers/specs/2026-09-30-inquiry-report-design.md`(대표 2026-09-30, "본사가 과제를 만든다"). 이 문서는 그 위에 **학생이 시작하는 길**을 더한다. 본사 과제 길은 그대로 남는다.
- 바뀌지 않는 대표 원칙: Q-4(논문 2편·기사 1건·도서 1권), Q-5(선정적 도서 금지), Q-6(아무것도 지어내지 않는다 — 확인한 자료만 보인다), Q-7~Q-9(차례·칸·희망 진로).

## 1. 목적

학생마다 융합해서 쓰고 싶은 과목이 다르다. 본사가 과제를 만들어 주는 대신 **학생이 과목 2개와 주제를 고르고**, AI가 탐구 문제 초안과 검색어를 내주고, 학생은 바로 쓰면서 자료를 찾아 넣고, 원장은 자료를 열어 보고 확인함만 찍는다. 제출은 확인된 자료가 대표 원칙을 채웠을 때만 된다.

## 2. 결정

| 번호 | 결정 |
|---|---|
| S-1 | 메뉴·제목은 「교과융합탐구보고서」(본사·원장·학생 화면). 홈페이지 공개 메뉴의 「탐구보고서」(RED 보고서 페이지)는 그대로. |
| S-2 | 과목 선택 권한은 학생. 제작소 과목 다섯(국어·영어·수학·사회·과학) 중 2개. |
| S-3 | 주제는 자유 한 줄. 비우면 배정된 서논술 대주제(제목·핵심 질문)를 추천한다. |
| S-4 | AI는 **탐구 문제·검색어만** 만든다. 자료의 제목·저자·주소는 만들지 않는다(Q-6). |
| S-5 | 자료는 **학생이 찾아 넣고**, 원장은 열어 보고 확인함을 찍거나 이유와 함께 돌려보낸다. |
| S-6 | 학생은 문제가 정해지면 **바로 쓴다**. 원장 승인을 기다리지 않는다. |
| S-7 | **제출 관문**: 확인된 논문 2·기사 1·도서 1(지금 게시 관문과 같은 수). 모자라면 무엇이 몇 개 더 필요한지 단추 옆에 보인다. |
| S-8 | 지금 과제 틀(inquiry_tasks·inquiry_assignments·inquiry_reports)을 그대로 쓴다. 학생 탐구 = 학생 한 명만의 과제 줄 하나 + 배정 하나. 새 표 없음. |
| S-9 | [다시 만들기]는 탐구 하나에 1회(AI 호출 최대 2번). AI가 실패하면 학생이 문제 세 개를 직접 적어 시작한다 — 막지 않는다. |

## 3. 화면 흐름

**학생** — 교과융합탐구보고서 → [새 탐구 시작]
1. 과목 2개 고르기, 주제 한 줄(비우면 대주제 추천 문구가 자리에 보임), [문제 만들기].
2. AI 초안: 질문형 제목·부제, 탐구 문제 가·나·다, 검색어(논문용·기사용·도서용). 학생이 문제 문장을 고칠 수 있다. [다시 만들기] 1회. [이 문제로 시작] → 쓰기 화면.
3. 쓰기 화면은 지금 그대로. 위에 「내 자료」 칸: 종류(논문·기사·도서)·제목·저자(기자)·연도(기사는 날짜)·학술지/매체/출판사·URL. 자료마다 상태 — 확인 기다리는 중 / 확인함 / 돌려보냄(이유). 검색어 묶음이 칸 위에 보인다. 참고문헌은 확인된 자료만 자동으로 들어간다(지금과 같음).
4. [제출]은 관문(S-7)을 채우면 켜진다. 모자라면 "논문 1편 더 필요" 식으로 단추 옆에.

**원장** — 교과융합탐구보고서 → 「학생이 시작한 탐구」 목록(본사 과제 목록 아래)
- 학생별 줄: 이름·과목·주제·자료 수(확인함/전체)·진행률·상태. 확인 기다리는 자료가 있으면 배지.
- 열면 자료 목록: URL 열기 → [확인함] / [돌려보내기](한 줄 이유). 보고서 보기·인쇄·다시 쓰게 하기·목차 바꾸기는 지금 그대로.

**본사** — 과제 목록에는 본사 과제만. 학생 탐구는 본사 화면에서 읽기만(문제 생기면 볼 수 있게), 고치지 않는다.

## 4. 자료 모양과 DB (마이그레이션 0019)

`inquiry_tasks`에 열을 더한다.
- `origin text not null default 'hq' check (origin in ('hq','student'))`
- `owner_student_id uuid references students(profile_id)` — 학생 탐구의 주인(hq 는 null). 같은 학생이 여러 번 시작해도 된다.
- `topic text not null default ''` — 학생이 적은 주제 한 줄
- `search_terms jsonb not null default '{}'` — `{ paper: string[], news: string[], book: string[] }`
- `theme_id`(있는 열) — 대주제 추천으로 시작했으면 그 대주제, 자유 주제면 null
- 학생 탐구의 `status`는 만들 때부터 'published'(원장·학생에게 보이는 조건이 지금 그대로라서). 본사 과제 목록은 `origin = 'hq'`로 거른다.

`questions`·`sources`는 지금 모양(`lib/inquiry/schema.ts`). `InquirySource`에 `returned: { reason, at } | null` 을 더한다(기본 null).
- 학생이 자료를 고치면 그 자료의 `verified`는 null 로 돌아간다(고친 뒤 재확인). `returned`도 지운다.
- `verified`는 원장만 찍는다. 학생이 보낸 자료에서 서버가 `verified`를 떼고, DB 에 있던 자료와 id 로 맞춰 **내용이 같은 것만** `verified`를 그대로 둔다.

`inquiry_assignments`는 [이 문제로 시작]을 누를 때 함께 만든다: `student_id`=본인, `academy_id`=students 줄의 학원, `assigned_by`=본인, `outline`=기본값. 원장이 지금처럼 목차를 바꿀 수 있다.

`inquiry_reports`는 그대로.

## 5. AI 초안 (`lib/inquiry/draft.ts`)

- 넣는 것: 학교급·학년, 과목 2개, 주제(또는 대주제 제목·핵심 질문). 학생 글은 넣지 않는다.
- 받는 것(zod): `{ title(질문형, 120자), subtitle(160자), questions: [{ key: '가'|'나'|'다', text(120자), lens }], search_terms: { paper: string[3], news: string[3], book: string[3] } }`. 자료 제목·저자·URL 은 스키마에 없다 — 모양이 어긋나면 실패로 처리한다.
- 규칙: 가=과목 A의 눈, 나=과목 B의 눈, 다=융합. 두 과목 모두 성취기준 원문 안(수학·과학은 학년 단원 엄수, 나머지는 중1~3 안에서 유연). 초·중학생 말. 제작소 규칙 중 해당되는 것(조건은 지침이지 풀이 힌트가 아님, 자연스러운 문장, 객관식 없음)을 그대로 쓴다.
- 모델: `MODELS`에 `draft: 'claude-sonnet-5'` 추가. effort 'low'. 고정 응답 `data/studio-fixtures/inquiry-draft.json`(mock 모드·시험·시연).
- 호출 수: 탐구 하나에 최대 2번(S-9). 서버가 과제 줄의 `draft_count`(0019 에 `smallint default 0`)로 센다.
- 실패: 학생 화면에 "지금은 문제를 만들 수 없어요. 문제를 직접 적어 시작할 수 있어요." + 빈 문제 칸 세 개.

## 6. 권한 (RLS, 0019)

- 학생: `origin='student' and owner_student_id = auth.uid()` 인 과제 줄을 insert·select·update. update 는 자기 배정의 보고서가 제출 전(`inquiry_reports.submitted_at is null` 또는 보고서 없음)일 때만. `verified`를 못 찍는 것은 §4 의 서버 규칙이 막는다(DB 열 단위 제한은 두지 않는다).
- 학생: 자기 배정(inquiry_assignments) insert(`student_id = auth.uid()`, `academy_id = current_academy_id()`).
- 원장: 자기 학원 학생의 학생 탐구 줄 select·update(자료의 verified·returned 만 바꾼다 — 서버 액션이 다른 칸은 건드리지 않는다). 퇴원 학생(enrolled=false)의 탐구는 목록에서 뺀다(`enrolledIds`).
- 본사: select 전체(지금 admin 정책이 이미 for all 이면 그대로).

## 7. 제출 관문

`submitInquiry`(학생 서버 액션)에서 과제가 `origin='student'`이면 `publishGate`의 자료 부분(확인된 논문 ≥ 2, 기사 ≥ 1, 도서 ≥ 1)을 본다. 모자라면 제출하지 않고 열쇠 목록을 돌려준다 → 화면이 문구(`app.inquiry.gate`)로 보여 준다. 본사 과제는 관문 없음(지금과 같음).

## 8. 시험

- `lib/inquiry/draft.ts`: 스키마가 자료 제목·URL 을 거부, fixture 가 스키마를 통과, 프롬프트에 과목 2개·주제·학년이 들어감.
- 학생 액션: 과목 2개 아니면 거부, 2회 초과 호출 거부, 자료 저장 시 verified 떼기·고친 자료 재확인, 제출 관문.
- 원장 액션: 다른 학원 학생 거부, 확인함·돌려보내기만 바꿈, 퇴원 학생 목록 제외.
- 화면: 학생 시작 화면·자료 칸·원장 목록을 서버 렌더로 문구 확인(지금 inquiry 시험 틀 재사용).
- 가짜 DB(`tests/fixtures/fake-db.ts`)로 데이터 함수, `tests/inquiry-data.test.ts`에 학생 탐구 사례 추가.

## 9. 범위 밖(뒤로)
