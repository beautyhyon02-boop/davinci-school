# 3주차 설계 — 수업 운영: 배정·퀴즈·답안·AI 채점(원장 검수)·교재

이 문서는 대표님이 읽고 이해하실 수 있도록 썼습니다. 기술 용어는 처음 나올 때 풀어 쓰고, 각 부분에 예시를 넣었습니다. 코드를 쓰는 사람은 이 문서를 "무엇을 만들지"의 기준으로 삼습니다.

## 0. 한 장 요약

2주차까지 본사가 문항 세트를 만들어 게시하는 화면을 만들었습니다. 3주차는 그 세트로 **실제 수업을 운영하는 화면**입니다.

1. 원장님이 학생 계정을 만들고, 게시된 세트를 학생들에게 **배정**합니다.
2. 학생은 수업 진도에 맞춰 열린 차시의 **퀴즈**를 풀고(즉시 채점), 서술형·논술형 **답안**을 씁니다.
3. 노트북이 없는 반은 **교재를 인쇄**해 종이로 풀고, 원장님이 **사진을 올리면 AI가 글자로 읽어** 같은 흐름에 넣습니다.
4. 답안이 제출되면 **AI가 채점 초안**(점수·근거·잘한 점·보완할 점)을 만듭니다.
5. **원장님이 초안을 검수**해 점수와 피드백을 그대로 두거나 고쳐서 **확정·공개**합니다. 학생은 확정본만 봅니다.
6. 학생은 피드백을 보고 **재도전**(다시 쓰기)할 수 있고, 1회차와 2회차 결과가 나란히 남습니다.

이번 설계에서 새로 정한 큰 결정 다섯 가지:

| 결정 | 내용 | 이유 |
|---|---|---|
| 퀴즈 | 학생이 앱에서 풀고 자동 채점, 원장님이 정답률을 봄 | 차시별 이해도 기록이 상품 가치 |
| 제출 단위 | 차시마다 제출·채점 (세트 한 번에 아님) | 원장님이 다음 수업 전에 결과를 보고 지도 |
| 결과 공개 | 퀴즈는 즉시, 서논술은 원장 확정 후 | AI 실수가 학생·학부모에게 바로 가지 않게 |
| 채점 주체 | AI는 초안, 원장이 검수·조정·확정 (HITL) | 본사 기준 + 현장 판단 둘 다 남김 |
| 종이 수업 | 교재 인쇄 + 사진 읽기(원장이 확인 후 채점) | 노트북 없는 반도 같은 흐름 |

> HITL(Human In The Loop): "사람이 중간에 확인한다"는 뜻. AI가 한 일을 사람이 검수한 뒤에야 효력이 생기는 방식.

## 1. 등장인물과 하루의 흐름 (예시)

예시 인물: **박 원장**(다빈치 대구수성원), 학생 **김민준**(중1), 세트 **「학교 축제, 일회용품을 줄이자」 수학**(5차시, 서술형 2 + 논술형 1 = 22점).

**월요일, 수업 전** — 박 원장이 `/teacher/students`에서 김민준을 등록합니다. 아이디 `dgss-007`과 초기 비밀번호가 한 번 화면에 뜹니다. 인쇄해 학생에게 줍니다. 이어서 `/teacher/items`에서 수학 세트를 열고 [배정하기] → 반 학생 8명 체크, 마감일 10/31, 재도전 허용, "1차시까지 열기" → [배정].

**월요일, 1차시 수업** — 학생들은 노트북으로 `/student`에 로그인해 1차시 탭을 엽니다. 자료 A(부스별 컵 개수 표)를 보며 수업을 듣고, 끝에 퀴즈 3문항을 풉니다. [제출]하면 바로 정답·해설이 뜨고 "3문항 중 2개 정답". 박 원장 화면에는 반 전체 정답률 표가 생깁니다. 2번 문항을 6명이 틀렸으니 다음 시간에 다시 설명하기로 합니다.

**수요일, 3차시** — 박 원장이 "3차시까지 열기"를 누릅니다. 3차시에는 퀴즈와 **서술형 1**("자료 B의 수치 하나를 근거 문장으로 쓰시오", 3점)이 있습니다. 김민준이 답안을 쓰고 [제출]합니다. 20초 뒤 박 원장 화면에 "검수 대기 1건"이 뜹니다.

**수요일 저녁, 검수** — 박 원장이 김민준 카드를 엽니다. AI 초안: 점수 2/3, 근거 "'올해 플라스틱컵이 405개로 가장 많이 늘었다'라고 수치를 정확히 인용함", 잘한 점 2개, 보완할 점 "작년과 비교한 증가량(115개)까지 쓰면 3점 기준을 채웁니다". 박 원장은 점수는 그대로 두고 보완할 점에 한 문장을 덧붙인 뒤 [수정하여 확정]. 김민준 화면에 결과가 공개됩니다.

**목요일, 재도전** — 김민준이 결과를 보고 [다시 써 보기]를 눌러 2회차 답안을 씁니다. 다시 AI 초안 → 원장 확정. 이번엔 3/3. 박 원장 화면에 "1회차 2점 → 2회차 3점"이 나란히 보입니다.

**종이로 하는 반** — 이 원장은 노트북이 없어 [학생용 교재 인쇄]로 소책자를 뽑아 수업합니다. 3차시 뒤 답안지를 걷어 사진을 찍고 `/teacher/assignments`에서 [사진 올리기] → 학생·차시 선택 → 업로드. AI가 퀴즈 답 3개와 서술형 답안을 글자로 읽어 칸에 채워 줍니다. 원장님이 잘못 읽힌 글자를 고치고 [저장·채점]. 그 뒤는 앱에서 푼 학생과 똑같습니다.

## 2. 역할과 권한

| 역할 | 할 수 있는 것 | 할 수 없는 것 |
|---|---|---|
| 학생 | 자기 배정 보기, 열린 차시의 퀴즈 풀기(1회), 답안 쓰기·임시저장·제출, 공개된 결과 보기, 재도전 | 제출한 답안 수정, 채점 보기(공개 전), 남의 것 보기 |
| 원장 | 자기 원 학생 관리, 배정, 차시 열기, 퀴즈 정오 뒤집기(단답형), 사진 올리기, AI 초안 검수·조정·확정·공개, 코멘트, 재채점 요청, 교재 인쇄 | 다른 원 데이터, AI 초안 원본 수정, 본사 문항 수정 |
| 본사(관리자) | 전부 보기, 재채점 요청 처리(이번엔 DB에서), AI 초안과 확정본 비교 | — |

권한은 화면이 아니라 **DB 행 단위 보안(RLS)**으로 막습니다. 주소를 알아도 남의 원 데이터는 열리지 않습니다.

## 3. 장부 구조 (데이터)

> "장부"는 데이터베이스의 표를 뜻합니다. 아래 표 하나가 엑셀 시트 하나라고 보시면 됩니다.

### 3.1 배정 `assignments` (기존 표 + 열 하나)

| 열 | 뜻 | 예시 |
|---|---|---|
| item_set_id, item_set_version | 어떤 세트의 몇 판인지 (게시 판 고정) | 수학 세트, 1판 |
| academy_id, student_id | 어느 원, 어느 학생 | 대구수성원, 김민준 |
| assigned_by | 배정한 원장 | 박 원장 |
| due_at | 마감일 | 2026-10-31 |
| allow_retry | 재도전 허용 | 예 |
| **open_lessons (새)** | 열린 차시 수 | 3 |
| closed | 마감 처리 | 아니오 |

규칙: 한 학생에게 같은 세트를 두 번 배정할 수 없다(중복 방지). 세트 내용은 게시 판(스냅샷)에서 읽으므로 본사가 나중에 2판을 게시해도 진행 중인 배정은 1판 그대로다.

### 3.2 퀴즈 응답 `quiz_responses` (새)

| 열 | 뜻 | 예시 |
|---|---|---|
| assignment_id | 어느 배정 | 김민준의 수학 세트 |
| lesson_no, quiz_no | 몇 차시, 몇 번 문항 | 1차시 2번 |
| response | 학생이 고른/쓴 답 | "③" 또는 "상대도수" |
| correct | 정답 여부 | 예/아니오 |
| source | 입력 경로 | 학생 / 사진 |
| answered_at | 답한 시각 | |
| overridden_by, overridden_at | 원장이 정오를 뒤집었으면 누가 언제 | |

규칙: 학생·차시·문항에 한 줄. 정답 여부는 **저장할 때 서버가** 세트 스냅샷의 정답과 비교해 넣는다. 선택형은 번호 일치, 단답형은 앞뒤 공백·띄어쓰기·대소문자를 무시하고 비교한다(예: "상대 도수" = "상대도수"). 단답형 오판정은 원장이 뒤집을 수 있다.

### 3.3 답안 `answers` (새, 기존 `submissions`를 대체)

| 열 | 뜻 | 예시 |
|---|---|---|
| assignment_id | 어느 배정 | |
| item_no | 문항 번호 (1·2·3, 세트의 평가 문항 순서) | 1 = 서술형 1 |
| attempt | 회차 (1 = 처음, 2 = 재도전) | 1 |
| body | 답안 본문 | "올해 플라스틱컵이 405개로…" |
| source | 입력 경로 | 학생 타이핑 / 사진 읽기 / 원장 대신 입력 |
| photo_path | 사진이 있으면 저장 위치 | |
| entered_by | 입력한 사람 | 김민준 또는 박 원장 |
| saved_at | 마지막 임시저장 시각 | |
| submitted_at | 제출 시각 (비어 있으면 아직 작성 중) | |

규칙:
- 배정·문항·회차에 한 줄. 2회차는 1회차가 **공개된 뒤**에만 만들 수 있고, 배정의 재도전 허용이 켜져 있어야 한다.
- **제출 시각이 찍히면 본문을 바꿀 수 없다.** 화면뿐 아니라 DB 규칙(트리거)으로 막는다. 잘못 제출한 경우는 원장님이 재도전으로 열어 준다.

### 3.4 채점 `gradings` (새 구조)

답안 한 줄에 채점 한 줄. **AI 초안**과 **원장 확정본**을 같은 줄의 다른 열에 둔다.

| 구역 | 열 | 뜻 |
|---|---|---|
| 공통 | answer_id, academy_id | 어느 답안, 어느 원 |
| 공통 | status | `pending`(AI 호출 중) → `drafted`(검수 대기) → `confirmed`(확정·공개) / `failed`(AI 실패) / `rejected`(50자 미만 등, 채점 안 함) |
| AI 초안 | ai_criteria | 요소별 점수와 근거 인용 (아래 예시) |
| AI 초안 | ai_score | 문항 점수 |
| AI 초안 | ai_strengths, ai_improvements | 잘한 점[], 보완할 점[] |
| AI 초안 | model, input_tokens, output_tokens, error | 모델명, 토큰 수, 오류 |
| 확정본 | final_criteria, final_score | 원장이 확정한 요소별 점수·문항 점수 |
| 확정본 | final_strengths, final_improvements | 원장이 확정한 잘한 점·보완할 점 |
| 확정본 | teacher_comment | 원장 코멘트 |
| 확정본 | adjust_note | 조정 이유 (선택) |
| 확정본 | confirmed_by, confirmed_at | 확정한 사람·시각 (= 공개 시각) |
| 확정본 | updated_at | 확정 뒤 다시 고친 시각 |
| 기타 | regrade_requested | 재채점 요청 여부 |

규칙:
- **AI 초안 열은 서버(AI)만 쓰고, 한 번 채워지면 바꿀 수 없다.** 원장님은 확정본 열만 바꿀 수 있다. 둘 다 DB 규칙으로 막는다.
- [그대로 확정]을 누르면 AI 초안이 확정본으로 복사된다. [수정하여 확정]은 원장님이 고친 값이 확정본이 된다. 어느 쪽이든 `confirmed_at`이 찍히면 학생에게 공개된다.
- 확정 뒤에도 원장님이 다시 열어 고칠 수 있다(`updated_at` 갱신). 학생은 항상 최신 확정본을 본다.
- [AI 다시 채점]은 새 채점 줄을 만들지 않고, 같은 줄의 AI 초안 열을 지우고 다시 채운다 — 단, 이미 확정된 줄은 다시 채점할 수 없다(확정을 먼저 풀어야 함).

**AI 초안 예시 (서술형 1, 3점 만점)**

```
ai_score: 2
ai_criteria: [
  { name: "수치 인용의 정확성", points: 2, max: 3,
    evidence: "올해 플라스틱컵이 405개로 가장 많이 늘었다" ,
    note: "수치는 정확하나 작년과의 비교가 없음" }
]
ai_strengths: ["자료 B에서 올해 수치를 정확히 골라 썼습니다.",
               "'가장 많이 늘었다'처럼 비교 표현을 근거 문장에 넣었습니다."]
ai_improvements: ["3점 기준은 '작년 대비 변화'까지 쓰는 것입니다.
                   '작년 290개에서 올해 405개로 115개 늘었다'처럼 두 해를 함께 쓰면 됩니다."]
```

**논술형(16점)**은 `ai_criteria`가 4요소(예: 자료 활용 / 과학적 근거 / 제안의 타당성 / 글의 구성) 각 0~4점으로 들어가고, 합이 문항 점수가 된다.

### 3.5 종합 점수·등급

따로 저장하지 않고 **화면에서 계산**한다. 같은 회차의 세 문항이 모두 `confirmed`이면, 확정 점수 합(22점 만점)을 세트 스냅샷의 등급표(1~7등급, 상/중/하)에 대어 보여 준다. 재도전이 있으면 회차별로 따로 계산해 나란히 보여 준다.

예: 서술형 1 = 2점, 서술형 2 = 3점, 논술형 = 12점 → 합 17점 → 등급표에서 "15~17점 = 3등급, 중".

### 3.6 사진 저장소

`answer-photos` 버킷(비공개). 경로 `원ID/배정ID/차시-시각.jpg`. 읽기는 그 원의 원장과 본사만, 쓰기는 원장만. 자료 이미지 버킷(`materials`, 공개)과는 다르다 — 학생 이름과 답안이 찍혀 있으므로 절대 공개하지 않는다.

### 3.7 행 단위 보안(RLS) 요약

| 표 | 학생 | 원장 | 본사 |
|---|---|---|---|
| assignments | 자기 것 읽기 | 자기 원 읽기·쓰기 | 전부 |
| quiz_responses | 자기 것 읽기·쓰기(열린 차시만) | 자기 원 읽기, 정오 뒤집기 | 전부 |
| answers | 자기 것 읽기·쓰기(제출 전까지) | 자기 원 읽기·쓰기(사진·대신 입력) | 전부 |
| gradings | 자기 것 중 `confirmed`만, 확정본 열만 읽기 | 자기 원 읽기, 확정본 열 쓰기 | 전부 |

학생이 채점 줄을 읽을 때 AI 초안 열이 보이지 않도록, 학생용 조회는 확정본 열만 내보내는 **뷰(view)**를 거친다.

## 4. 원장 화면 `/teacher`

### 4.1 첫 화면 (대시보드)
"검수 대기 N건 · 진행 중 배정 N개 · 학생 N명"과 바로가기 세 개. 검수 대기가 있으면 맨 위에 눈에 띄게.

### 4.2 학생 관리 `/teacher/students`
- 목록: 이름, 학교급·학년, 아이디, 배정 수, 마지막 접속.
- [학생 추가]: 이름·학교급·학년 → 아이디(`원코드-번호`, 예 `dgss-007`)와 초기 비밀번호(8자, 헷갈리는 글자 제외) 자동 발급 → **한 번만 표시**되는 안내 카드(인쇄·복사). 닫으면 다시 볼 수 없고, 잊으면 [비밀번호 초기화].
- 계정은 서버가 본사 권한으로 만들고 `students` 표에 원·학년·번호를 기록한다. 번호(`seq`)는 원별로 1부터 순서대로 DB 함수가 매긴다(동시에 두 명을 만들어도 겹치지 않게).

### 4.3 배정하기 `/teacher/assignments/new?set=…`
세트 미리보기의 [배정하기]에서 들어온다.
- 학생 목록 체크(전체 선택 가능). 세트 학년과 다른 학생은 노란 경고만(막지 않음). 이미 이 세트가 배정된 학생은 회색.
- 마감일, 재도전 허용(기본 켬), 처음 열 차시 수(기본 1).
- [배정] → 학생 수만큼 배정 줄 생성 → 배정 현황으로 이동.

### 4.4 배정 현황 `/teacher/assignments`
- 세트별 묶음 카드: 세트 이름, 학생 수, 열린 차시, **검수 대기 N건**, 마감일.
- 묶음을 열면 `/teacher/assignments/[set]` (같은 세트를 받은 이 원 학생 전체):
  - **차시 열기**: "○차시까지 열기" 단추. 기본은 반 전체에 적용, 학생별로 다르게도 가능(예: 결석생만 2차시).
  - **퀴즈 현황**: 차시 탭마다 학생 × 문항 표. 정답 초록, 오답 빨강, 미응답 회색. 문항별 정답률을 열 머리에. 단답형 셀을 누르면 학생 답이 보이고 [정답 처리]/[오답 처리]로 뒤집을 수 있다.
  - **답안·검수**: 학생별 카드. 문항마다 상태 배지 — 미제출 / 채점 중 / **검수 대기** / 공개됨 / 재도전 중 / 실패 / 다시 쓰기 요청됨(50자 미만). 카드를 열면 §4.5.
  - **[사진 올리기]**: §4.6.
  - 마감·재도전 설정 바꾸기.

### 4.5 검수 화면 (카드 안)
왼쪽에 학생 답안(재도전이면 1회차와 2회차 나란히, 1회차 확정 결과 접어 두기), 오른쪽에 AI 초안이 **수정 가능한 칸**으로:
- 요소별 점수(숫자 칸, 0~최대), 근거 인용(읽기 전용), 문항 점수(요소 합으로 자동)
- 잘한 점·보완할 점: 문장마다 고치기·지우기, [문장 추가]
- 원장 코멘트(자유), 조정 이유(선택, 점수를 바꿨을 때만 표시)
- 단추: **[그대로 확정]**(초안을 손대지 않았을 때) / **[수정하여 확정]** / [AI 다시 채점] / [재채점 요청(본사)]
- 확정된 카드는 "공개됨 · 박 원장 · 10/1 20:13"이 보이고 [다시 고치기]로 열 수 있다.
- 세 문항이 모두 확정되면 카드 위에 종합 점수·등급이 뜬다.

### 4.6 사진 올리기
1. 학생과 차시를 고른다(여러 학생을 한 번에: 사진마다 학생을 지정).
2. 사진 업로드(JPG·PNG·HEIC, 10MB 이하, 여러 장).
3. 서버가 AI에게 "학생용 교재 ○차시 쪽 양식"과 함께 사진을 보내 **글자로만 옮기게** 한다(채점 아님). 결과가 퀴즈 답 3칸 + (그 차시에 있으면) 서술형/논술형 답안 칸에 채워진다. AI가 자신 없다고 표시한 부분은 노란 배경.
4. 원장님이 읽은 내용을 고친 뒤 **[저장·채점]**. 그때부터 학생이 앱에서 입력한 것과 같은 길로 간다(정오 판정, 답안 제출, AI 채점 초안). 입력 경로는 "사진"으로 남고 원본 사진도 연결된다.
5. 같은 학생·차시에 이미 앱 입력이 있으면 덮어쓰지 않고 경고한다.

### 4.7 교재 인쇄
세트 미리보기(`/teacher/items/[set]`)에 [학생용 교재 인쇄] [교사용 교재 인쇄]. §7.

## 5. 학생 화면 `/student`

글자 크게, 단추 적게, 한 화면에 한 가지 일.

### 5.1 내 과제 `/student`
배정된 세트가 카드로: 대주제·과목·마감일, "3차시까지 열림 · 퀴즈 2/3 완료 · 답안 1/3 제출", 배지(할 일 있음 / 선생님 확인 중 / 결과 나옴).

### 5.2 과제 화면 `/student/assignments/[id]`
- 위에 차시 탭 1~6. 열린 차시만 누를 수 있고, 안 열린 차시는 자물쇠.
- 차시 안: 차시 핵심질문 → 그 차시 자료(표·자동 그래프·글) → 그 차시에 있는 것만:
  - **퀴즈**: 선택형은 큰 단추, 단답형은 짧은 칸. 3문항을 다 고르면 [제출]. 제출 즉시 정답·해설·"3문항 중 2개 정답". **한 번 제출하면 다시 풀 수 없다**(원장님이 되돌릴 수 있음).
  - **서술형/논술형**(그 차시에 배치된 문항만): 문항, 조건(분량·필수 요소·형식), 큰 입력칸, 글자 수. **자동 임시저장**(30초마다와 칸을 떠날 때). [제출] → 확인창 "제출하면 고칠 수 없어요. 제출할까요?" → 제출. 이후 읽기 전용, "선생님이 확인 중이에요".
  - 50자 미만으로 제출하면 서버가 제출 시각을 찍지 않고 돌려보낸다. "조금 더 써 보세요. 조건을 다시 읽어 보세요"가 뜨고 같은 칸에서 이어 쓸 수 있다(재도전 회차를 쓰지 않음, 채점 줄도 만들지 않음).

### 5.3 결과 (같은 화면, 공개된 문항부터)
- 문항 점수(예: 서술형 1 · 2/3점), 논술형은 4요소 점수와 근거 문장, **잘한 점**, **보완할 점**, 원장 코멘트. 학생은 확정본만 본다.
- 세 문항이 모두 공개되면 맨 위에 **22점 만점 점수 · 1~7등급 · 상/중/하**.
- 재도전 허용이면 공개된 문항 아래 [다시 써 보기] → 같은 문항의 2회차 칸(1회차 답안·피드백을 옆에 접어 둠) → 제출 → 다시 검수·공개 → 1회차·2회차 점수 나란히.

### 5.4 계정
로그인은 원장님이 준 아이디·비밀번호. 학생 화면에는 비밀번호 변경만. 잊으면 원장님이 초기화.

## 6. AI 채점과 사진 읽기

### 6.1 채점 호출 (문항 하나 = 호출 하나)
- **언제**: 학생 [제출] 또는 원장 [저장·채점] 직후. 서버가 바로 실행(문항 제작소와 같은 방식, Vercel 함수 최대 5분). 채점 줄은 먼저 `pending`으로 만들고, 결과가 오면 `drafted`로.
- **모델**: `claude-sonnet-5`. 응답은 정해진 틀(JSON)로 강제.
- **입력**: 문항 본문·조건, 그 문항의 채점표(서술형: 점수 단계별 기대와 예시 / 논술형: 4요소 × 0~4 기준표), 예시 답안 상·중·하와 그 점수, 학생 학년, 학생 답안, 세트 규칙(학년 어휘, 존댓말).
- **출력**: §3.4의 `ai_*` 값. 요소마다 **답안에서 인용한 근거 문장**을 반드시 붙인다. 보완할 점은 **한 단계 위 기준**에서 뽑는다("다음 점수로 가려면 …").
- **거르기**: 50자 미만은 제출 자체를 받지 않는다(§5.2). 길이는 충분하지만 문항과 무관한 답안(예: 다른 문항의 답, 의미 없는 글자)은 AI가 짧게 판정해 `rejected`("다시 써 보세요")로 두고 제출을 되돌린다. 비용 절감과 장난 제출 방지.
- **실패**: 형식 오류는 1회 자동 재시도. 재실패는 `failed` + 원장 화면 [다시 채점].
- **비용 기록**: 호출마다 토큰 수 저장. 원별·월별 합계 화면은 발표 뒤.
- **가짜 응답 모드**: 키가 없어도 화면 흐름을 시험할 수 있게 채점 fixture를 둔다(상·중·하 답안 3종).

### 6.2 사진 읽기 (원장 화면)
- AI에게 사진과 "이 종이의 구조"(학생용 교재 양식: 머리띠에 문항 번호·이름, 퀴즈 3칸, 답안 칸)를 함께 보내 **글자로 옮기게만** 한다. 출력 틀: `{ quiz: [답1, 답2, 답3], answer: "…", uncertain: ["…"] }`.
- 읽기 결과는 바로 저장되지 않는다. 원장님이 확인·수정 후 [저장·채점]해야 답안·퀴즈 응답이 생긴다.
- 손글씨 인식이 어려운 경우(흐림, 기울어짐)는 "다시 찍어 주세요" 안내와 함께 빈 칸으로 돌려준다.

### 6.3 검수 뒤
`drafted` → 원장 확정 → `confirmed`(=공개). §3.4·§4.5.

## 7. 교재·인쇄

세트 미리보기의 두 단추가 인쇄용 화면을 새 탭으로 연다. 브라우저 인쇄(Ctrl+P)로 A4 출력, 같은 창에서 "PDF로 저장" 가능. 별도 PDF 부품은 두지 않는다.

**학생용 교재**
1. 표지: 대주제·과목·학년·세트 판, 이름·반·날짜 칸
2. 대주제 소개 + 세트 핵심질문
3. 자료 A~E: 표는 인쇄용 선, 그래프는 화면과 같은 자동 그래프(흑백에서도 구분되게 무늬·번호)
4. 차시마다 새 쪽: 차시 번호·핵심질문·목표, 학생용 활동 안내, **퀴즈 3문항 + 답 칸**(선택형 ①②③④, 단답형 밑줄)
5. 평가 문항지: 서술형은 조건·분량 안내와 줄 칸, 논술형은 한 쪽 전체 줄 칸(500자 기준). 칸 위 머리띠에 "문항 번호 · 이름"을 **고정 위치**에 — 사진 읽기의 기준 양식

**교사용 교재**
1. 표지(교사용) + 준비물·일정 메모
2. 성취기준 원문·재구성·학습목표·핵심질문 두 층
3. 차시별: 지침서(도입 발문·전개·정리·비전공 주의점) + 퀴즈 **정답·해설** + 병합 가능 표시
4. 평가: 문항 + 채점표 전체 + 등급표 + 예시 답안 상·중·하 + 피드백 틀
5. 용어 풀이

**규칙**: 내용은 게시 판 스냅샷에서만(화면과 종이가 같은 판, 표지에 판 표시). 인쇄 전용 꾸밈(메뉴 숨김, 쪽 번호, 표·문항이 쪽 중간에서 잘리지 않게, 12pt 이상). 낱장은 인쇄 창의 쪽 범위로. 디자인판(삽화·색·글꼴)은 발표 뒤 Canva 연동과 함께.

## 8. 대주제 공유 자료 AI 생성 (제작소 보완)

지금은 공유 자료를 JSON으로 붙여넣어야 한다. 대주제 화면의 공유 자료 칸을 소개 칸과 같은 **[생성] [검토] [확정]** 흐름으로 바꾼다.
- [생성]: 확정된 소개 문구와 과목별 아이디어를 바탕으로 자료 A~D(표 2~3개 + 설명글 1~2개)를 만든다. 모든 수치는 가상이며 표끼리 합계가 맞아야 한다(검토 단계가 확인).
- 편집: 표는 칸별로, 글은 문장으로 고칠 수 있다. JSON 칸은 "고급"으로 접어 둔다.
- 확정 뒤 세트의 4단계(세트 자료)는 A~D 다음 글자부터 매긴다(이미 구현됨).

## 9. 시험 방법

- **자동 시험(코드)**: 정오 판정(선택·단답 정규화), 종합 점수·등급 계산, 재도전 회차 규칙, 열린 차시 판정, 사진 읽기 결과를 칸에 배치하는 규칙, 채점 입력 프롬프트 조립, 채점 응답 틀 검증, 인쇄용 쪽 구성(어느 내용이 어느 쪽에).
- **DB 규칙 시험**: 제출 뒤 답안 수정 금지, AI 초안 열 변경 금지, 원장의 확정본 열만 허용, 학생 뷰에 AI 초안이 안 보임 — 시험 계정(원장 2명, 학생 3명, 원 2곳)으로 확인.
- **채점 품질**: 대표님이 검토한 수학 세트로 상·중·하 예시 답안을 채점해 예상 등급대로 나오는지 확인. 어긋나면 채점 지시문을 고친다.
- **시뮬레이션**: 구현 뒤 대표님이 원장·학생 계정으로 한 반을 끝까지 돌려 보고 수정 목록을 만든다. 4주차 첫머리에 반영.

## 11. 용어 풀이

- **배정**: 원장님이 세트를 학생에게 주는 것. 배정 한 줄 = 학생 한 명 × 세트 하나.
- **차시**: 수업 한 시간 단위. 세트는 4~6차시.
- **회차**: 같은 문항에 답안을 쓴 횟수. 1회차 = 처음, 2회차 = 재도전.
- **AI 초안 / 확정본**: AI가 먼저 낸 채점과 원장님이 검수해 확정한 채점. 학생은 확정본만 본다.
- **스냅샷(판)**: 게시할 때 세트 내용을 통째로 보관한 것. 배정은 그 판에 묶인다.
- **RLS**: 데이터베이스가 행마다 "누가 볼 수 있는지"를 검사하는 규칙.
- **fixture(가짜 응답)**: API 키 없이 화면을 시험하기 위해 미리 써 둔 AI 답.
