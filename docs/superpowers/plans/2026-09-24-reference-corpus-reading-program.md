# 참고 자료 전체 학습 프로그램 (읽기 계획)

작성 2026-09-24 · 설계: `docs/superpowers/specs/2026-09-24-reference-corpus-design.md` · 말뭉치: `reference-corpus/` (git 제외, `scripts/extract_corpus.py`로 재생성, 190여 파일 약 41,000쪽)

**목표**: 교육부·평가원·시도교육청 공개 자료 전부를 읽어 다섯 지식 베이스(성취수준 표 · 문항·채점기준 예시 은행 · 과목별 규칙 · 서식 · 연구 문서)로 바꾸고, 그 위에서 "자료를 뛰어넘는" 차시안·서논술 문항 설계(새 스펙)를 쓴다. 지식·이해 / 과정·기능 / 가치·태도 세 축(2022 개정 = OECD Education 2030의 knowledge/skills/attitudes & values)으로 구조화해 수출 대응을 준비한다.

**원칙**
- 글자 추출·중복 제거·표 파싱은 스크립트(무료). AI는 뜻을 읽어야 하는 부분(원칙·절차·예시 문항·지도안·기재 예시)을 빠짐없이 읽는다.
- 같은 내용의 두 벌(연구보고서 ↔ 현장보급본, 중 ↔ 고 가이드북)은 한 벌만 정독하고 다른 벌은 차이만 본다.
- 산출물은 전부 저장소에 남긴다: `docs/research/corpus/<WP>-*.md`, `data/reference/<종류>/*.json`(출처 문서·쪽 포함).
- 작업 묶음(WP)마다 담당 에이전트 1명, 완료 뒤 검토 1명. 묶음 2~3개씩 병렬.

## 실행 순서

1. **1차(지금)**: WP1 · WP2 · WP4 병렬 → 검토
2. **2차**: WP5 · WP7 · WP8 병렬 → 검토
3. **3차**: WP6 · WP11 · WP3 병렬 → 검토
4. **4차**: WP9 · WP10 → 검토
5. **WP12** 종합 설계 → 대표님 검토 → 구현 계획(제작소 v2)

각 묶음의 담당 에이전트는 말뭉치(`reference-corpus/*.txt`)만 읽고, PDF 원본은 수식·표가 깨진 쪽에 한해 `pymupdf`로 그림 렌더링해 확인한다. 보고서에는 읽은 쪽 범위와 건너뛴 쪽 범위를 반드시 적는다.

## 완료 판정

- 모든 WP 보고서에 "읽은 범위 / 건너뛴 범위 / 발견 / 규칙안 / 서식안"이 있고, 예시 은행 항목마다 출처 문서·쪽이 있다.
- `data/reference/levels`가 standards DB의 초·중 성취기준 코드 95% 이상과 연결된다(연결 안 된 코드 목록 첨부).
- WP12 스펙이 "자료의 어느 부분을 그대로 쓰고, 어디를 넘어서는지"를 절마다 근거(문서·쪽)와 함께 적는다.
