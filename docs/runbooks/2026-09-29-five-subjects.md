**세트 구조(대표님 결정 2026-09-26)**: 세트 = 단원 = 교수 차시 3~5개(시연 세트는 5개). 매 교수 차시 끝에 이해 점검 퀴즈 3문항(마지막 교수 차시 포함). 세트 끝 평가는 **서술형 1문항 + 논술형 1문항**, 정확히 2문항이고, 둘 다 **5차시(마지막 교수 차시) 뒤 6차시 「단원 평가」**(60분 = 평가 안내 5 · 서술형 작성 15 · 논술형 작성 35 · 정리 5, 퀴즈 없음)에서 함께 본다. 두 문항 모두 분석적 채점표(요소별) + 총체적 상/중/하를 갖춘다. 조건은 논술형에만 2~4개(지침만), 서술형은 조건 없이 분량·형식만. **배점은 본사 가정**: 서술형 6점(요소 2~3개) + 논술형 16점(4요소 × 4) = 22점 — 7등급표(21~22 …)는 그대로이고, 대표님이 배점을 바꾸면 바꾸는 순서: ① `lib/studio/assessment-structure.ts`의 숫자(`SET_ITEMS`·`ASSESSMENT_SESSION`, 총점이 22가 아니면 `lib/studio/level-map.ts` `GRADE_TABLE_22`도) → 스키마·[TS]·5단계 프롬프트·검토 초점·화면 문구·규칙 문장(C-14·C-31·L-09·S-수-02, `lib/studio/structure-text.ts`가 만든다)이 따라 바뀐다 ② `npx vitest run tests/rules.test.ts`가 알려 주는 새 문장으로 스펙 부록 A의 C-14·C-31·L-09·S-수-02 행을 고친다 ③ 시연 fixture의 서술형 채점표(`scripts/upgrade-fixtures-v2.ts` PATCHES, 3요소 × 0~2)를 새 배점에 맞게 다시 쓰고 스크립트를 돌린다(배점이 안 맞으면 스크립트가 멈춘다). 2026-09-26 이전에 게시된 판(서술형 3점 × 2 + 논술형)은 고치지 않고 그대로 보이고 채점된다.

## A. 준비 (관리자, 생성 시작 전 1회, 약 20~30분)

순서대로 진행한다. 하나라도 빠지면 뒤 단계에서 저장 오류나 정답 유출로 나타난다.

### 1. 마이그레이션 0011을 **가장 먼저** 적용한다 (순서가 중요하다)

`studio-v2` 체크아웃에서, `supabase login`을 실행한 바로 그 터미널에서(토큰이 그 세션에만 저장된다):

```bash
supabase db push
```

무엇이 생기나: `item_sets`에 `unit_plan`·`reconstruction_detail`·`notice_plan` 세 열, 학생별 차시 안내장 표 `lesson_notices`(정책 정확히 2개 — `admin_all_lesson_notices`, `teacher_rw_lesson_notices`). 기존 `notices` 표는 홈페이지 공지사항용이라 이름이 겹쳐 다른 이름을 썼다(근거: `task-5-report.md` 배경 1). **0010 파일은 없다 — 0009 다음이 0011인 건 번호만 비어 있는 것이고, 빠뜨린 마이그레이션이 아니다.** 이 마이그레이션은 다시 실행해도 안전하다(열·표·정책 모두 "있으면 건너뜀").

**확인**: Supabase 대시보드 Table Editor에서 `item_sets`에 위 세 열이 보이고 `lesson_notices` 표가 새로 생겼는지, Authentication → Policies에서 `lesson_notices`에 정책이 정확히 2개(`admin_all_lesson_notices`, `teacher_rw_lesson_notices`) 있는지 확인한다.

**왜 이 순서가 중요한가 (db push가 배포보다 먼저여야 한다)**: 지금 배포돼 있는 main은 이 세 열도 `lesson_notices` 표도 전혀 읽지 않는다. 그래서 db push를 먼저 해도 지금 서비스는 안전하다. **반대로 하면**(main을 먼저 배포하고 db push를 나중에 하면) db push 전까지: 관리자 세트 화면이 전부 404(새 열을 select하기 때문), 모든 단계 생성 요청이 500, 게시와 2단계 JSON 편집이 저장 오류(saveFailed)로 실패, 안내장 초안 만들기가 `lesson_notices` 표 없음으로 실패한다. (학생·원장의 게시판 열람 화면은 계속 작동한다 — 이미 게시된 v1 스냅샷을 `upgradeSnapshot`으로 읽을 뿐 새 열이 필요 없다.) 그러므로 **db push(1번) → 병합·배포(2번)** 순서를 반드시 지킨다.

### 2. 그 다음에만 `studio-v2` → main 병합·배포

`studio-v2`가 최종 검토를 통과해 main에 병합된 뒤:

```bash
git push
```

Vercel은 main에 push되면 자동 배포된다. **Vercel 대시보드에서 확인할 것** (명령이 아니라 화면 확인):
- Deployments 탭에서 방금 커밋의 배포가 "Ready"인지 확인한다.
- Ready가 아니면 [Redeploy]를 눌러 다시 배포한다.
- Settings → Environment Variables에서 `ANTHROPIC_API_KEY`가 Production에 들어 있고 `AI_MOCK`이 **없는지**(있으면 실제 생성 대신 가짜 응답이 나온다) 확인한다.

### 3. API 키·과금 확인

- Anthropic 콘솔에서 API 키가 활성 상태이고 이번 주 5과목 생성(과목당 여러 번의 5단계 반복 포함)을 감당할 결제 한도가 있는지 확인한다.
- 확인 안 되면 생성 도중 "ANTHROPIC_API_KEY is not set" 또는 결제 관련 오류로 멈춘다.

### 4. 배포 뒤 smoke test

기존에 게시된 **v1** 세트 하나를 골라 원장 화면(`/teacher/items/[setId]`)과 학생 화면에서 열어 본다. v2 레이아웃으로 보여야 한다: 문항이 옛 구조 그대로 3개(서술형1·서술형2·논술형 — 새 구조로 바꾸지 않는다), 서술형 채점표가 요소 1개짜리로, 차시 시간 예산 합이 60분으로, 안내장 링크는 **없이**(v1 게시본은 안내장을 지원하지 않는다) 나온다. 기존 배정·채점 기록·재도전 이력은 그대로 남아 있어야 한다(스냅샷만 새 레이아웃으로 읽히고, 데이터는 바뀌지 않는다).

### 5. 생성 전 시간 측정 (5일차 시작 전에 한 번)

이미 만들어 둔 초안 세트가 있다면, 2~6단계는 v1 시절 확정(accepted) 상태로 남아 있어도 7단계는 "준비 전"이라 게시가 막힌다 — **2단계부터 다시 생성**해야 한다(3~7단계가 함께 초기화된다). 본격적으로 5과목을 돌리기 전에 실제 3단계 생성 한 번, 5단계 생성 한 번의 걸린 시간을 재 둔다: 단계 생성 API 라우트는 `maxDuration = 300`초이고, v2 출력은 v1보다 3~4배 크며 5단계는 `effort: 'xhigh'`로 호출한다. 300초에 가까워지면 **effort를 낮추지 말고** Vercel Fluid compute를 켜거나 플랜의 실행 시간 제한을 올린다.

### 6. 공유 자료 B의 정답 유출 패치 (필수 — 수학 서술형의 정답이 새어 있다)

## C. 과목별 생성 (관리자, 과목당 25~40분 — 생성 대기 포함)

1. 대주제 화면 → [세트 만들기] → 과목·소단원 선택 → 위 표의 성취기준 2~6개 체크 → 생성.
2. 세트 마법사는 **2단계부터 7단계까지**(0~1단계는 대주제 소개·성취기준 확정 시 이미 끝났다) 각 단계에서 [생성]→[검토]→[다음](=확정)을 반복한다. 단계 이름은 화면 탭 그대로다: 2 재구성·목표·핵심질문 / 3 차시 설계 / 4 자료 / 5 평가 / 6 교사용 지침서 / 7 안내장 틀.
3. 검토는 항상 **[TS] 정적 검사가 먼저** 돌고(모델 호출 없음), 통과해야 AI 검토로 넘어간다. [TS]에서 걸리면 모델을 부르지 않고 바로 실패로 표시된다 — 비용이 들지 않으니 [다시 생성]을 눌러도 된다.
4. 검토가 통과 못 하면 이슈 목록을 읽고 종류(`kind`)에 따라 대응한다:
   - **`fidelity`**(원문에 없는 표현, 재구성 문장이 성취기준 원문 어휘를 벗어남): [다시 생성].
   - **`coverage`**(성취기준 누락, 차시 배치와 문항 번호가 안 맞음) · **`quiz`**(퀴즈 개수·정답 문제, "퀴즈는 단답형만(선택지 금지)" — 2026-09-26 이전에 만든 초안의 선택형 퀴즈도 여기서 걸린다): [다시 생성].
   - **`level`**(등급 문장이 부사만 다르고 지식·과정·가치·태도 축이 안 갈림, 또는 `level_ref`가 7등급표와 안 맞음): [다시 생성] 1회, 그래도 실패하면 [JSON 편집]으로 척도 문장에 목적어·범위를 넣어 직접 고친다.
   - **`source`**(공개 자료·AI 보조 표시가 이번 세트 방침과 다름 — 첫 5세트는 전부 "자작"): 4단계를 다시 생성한다.
   - **`rubric`**(채점표 단계가 관찰 가능한 표현이 아니거나 0점 구분이 없음): [다시 생성].
   - **`notice`**(안내장 틀 문구 규칙 위반): 7단계를 다시 생성한다.
   - **`grade_level`**·**`other`**: 이슈 문구를 읽고 [다시 생성], 반복되면 [JSON 편집].
5. **검토 반복 한도는 모든 단계 3회다**(`MAX_ATTEMPTS`는 0~7단계 전부 3 — `lib/studio/max-attempts.ts`). 3번째도 실패하면 화면에 "생성이 반복해서 실패했습니다. [JSON 편집]으로 직접 입력해 주세요."가 뜬다. 이때 이슈가 가리키는 문항 번호·요소만 JSON에서 고치고 [검토]를 다시 눌러 통과를 확인한 뒤 [다음]으로 확정한다.
6. **단계를 편집하면 그 뒤 단계가 전부 초기화된다.** 예를 들어 확정된 5단계를 다시 편집하면 6·7단계는 "준비 전" 상태로 돌아간다(`lib/studio/edit-rules.ts`의 `LAST_STAGE = 7`까지 리셋). 앞 단계를 고칠 때는 뒤 단계를 다시 만들 시간을 감안한다.
7. 2단계 확정 뒤 핵심질문 후보 중 하나를 선택해 저장한다.
8. 7단계까지 확정되면 미리보기(패키지 화면)에서 교수 차시 카드 5개(퀴즈 3문항씩)·**6차시 단원 평가 카드**(레몬 테두리, 서술형 15분 + 논술형 35분)·문항 카드 2장(서술형 6점·논술형 16점, 둘 다 총체적 상/중/하)·안내장 틀(평가 요소 문구는 6차시에만)이 보이는지 확인한 뒤 [게시]한다. **게시 조건은 2~7단계가 전부 확정(`accepted`)이어야 한다**(`PUBLISH_STAGES = [2,3,4,5,6,7]`, `lib/studio/publish.ts`).
9. 원장 계정으로 `/teacher/items`에서 방금 게시한 세트를 열어 정답이 접혀 있는지(`<details>` 기본 닫힘) 확인한다.

## D. 시연 흐름 (원장·학생, 3A 절차 + 안내장)

3A(수업 운영) 시연 절차를 그대로 따르되, 서·논술형은 5차시 뒤 **6차시 단원 평가**에서 함께 본다(대표님 2026-09-26). 안내장은 교수 차시(퀴즈 결과)와 6차시(서술형·논술형 결과) 두 모양을 시연한다.

1. 원장: 학생 2명 추가 → 세트 [배정하기] → "처음 열 차시 수" 2 → 재도전 허용 체크.
2. 학생: 1·2차시 퀴즈 제출(교수 차시(시연 세트 1~5)는 차시마다 퀴즈 3문항, 서·논술형 없음).
3. 원장: "차시 열기"로 5차시까지 연다 → 학생이 3~5차시 퀴즈 제출.
4. 원장: "차시 열기"로 **6차시(단원 평가)**를 연다 — 학생 화면 탭 이름이 "6차시 · 단원 평가"로 보이고, 안내 한 줄(서술형 15분 · 논술형 35분)과 두 문항의 자료가 함께 보인다.
5. 학생: 서술형(6점) 답안 제출 → 논술형(16점) 답안 제출. 서술형 카드에는 "작성 조건" 머리글 없이 분량·형식만, 논술형 카드에는 번호 붙은 조건 2~4개가 보인다.
6. 원장: `/teacher/assignments/[setId]` → 서술형·논술형 검수 대기 카드 → 점수 확인/수정 → **확정**(HITL — 원장이 확정해야 결과가 학생에게 보이고 안내장 재료가 된다). 두 문항이 모두 확정되면 종합 점수(22점 만점)·등급이 뜬다.
7. 학생: [다시 써 보기]로 재도전 → 원장 확정 → 1·2회차 비교.
8. **안내장**: 배정 상세 화면의 "안내장 6차시" 링크 → [안내장 초안 만들기] → 서술형·논술형 결과 칸이 두 개(확정된 문항만) 들어간 AI 초안이 뜨면 문장 규칙 위반(린트) 여부 확인 → 필요하면 문장 칸만 고침(점수·정오는 못 고침) → 원장 한마디 입력 → [확정] → [인쇄]. 인쇄 버튼은 확정 후에만 나온다. 교수 차시(1~5)도 열려 있으면 퀴즈 결과만 담은 안내장을 만들 수 있다.
9. **종이 답안 문항**: 시연 세트(수학·과학)에는 이제 없다(수학의 종이 답안 도수분포표 서술형을 뺐다). 다른 과목 세트에서 생기면(세트당 최대 1개) 학생 화면에 입력 칸이 없고 "종이 답안(사진 제출)" 안내만 뜬다 — 사진 업로드 경로는 아직 없으므로(3B) 화면 안내 문구만 확인한다.

## F. 실패 시 기록·프롬프트 수정 흐름

무언가 실패하면 다음을 남긴다(어느 단계인지 모르면 재현이 안 된다):

1. **어느 단계에서 실패했는지**(2~7단계 중 어디, 생성인지 검토인지).
2. **[TS] 이슈 텍스트 원문**(검토 실패 카드에 그대로 나온다 — `{kind, detail}` 목록). `kind`가 `fidelity`/`coverage`/`quiz`/`level`/`rubric`/`source`/`notice`/`grade_level`/`other` 중 무엇인지 적는다.
3. **스크린샷**(문항 카드 또는 검토 이슈 화면). JSON 편집으로 고친 경우 고치기 전/후를 남긴다.

**프롬프트를 고쳐야 하는 경우**(같은 문제가 과목을 바꿔도 반복될 때만 — 한 세트의 일회성 실패는 JSON 편집으로 충분하다):
- 규칙 문장은 `lib/studio/prompts/rules/`(공통 `common.ts`, 차시 `lesson.ts`, 채점 `grading.ts`, 안내장 `notice.ts`, 과목별 `subjects/{과목}.ts`) 아래에 있다. ID(C-/L-/S-/G-/N-)와 부록 A가 1:1이므로, 부록 A(스펙 §부록 A)도 같이 고친다.
- 규칙을 고친 뒤에는 **2단계부터 다시 생성**한다(규칙 문자열은 매 단계 프롬프트의 system 블록에 들어가므로, 이미 확정된 단계는 새 규칙을 반영하지 않은 채로 남는다).
- 검토 초점(`REVIEW_FOCUS`)이나 [TS] 검사(`lib/studio/checks.ts`)를 고치는 쪽이면 개발자에게 넘긴다.

## G. 알려진 한계 (이번 5과목 생성에서 그대로 부딪히는 것)

- **사진 업로드 없음 — 종이 답안 문항은 앱 안에서 채점이 끝나지 않는다.** 종이 답안 문항(과목 세트마다 최대 1개)은 학생이 화면에서 직접 입력할 수 없다(서버도 저장·제출을 거부한다, `errors.paperOnly`). 사진 업로드 경로가 아직 없으므로(3B에서 구현 예정) 그 문항 점수는 채워지지 않고 종합 점수도 완성되지 않으며, 단원 평가 안내장에서도 그 문항 결과 칸이 빠진다. **시연 세트(수학·과학)에는 2026-09-26 구조 변경으로 종이 답안 문항이 없다**(수학 서술형 1 = 종이 도수분포표를 빼고 상대도수 서술형을 남겼다). 새로 만드는 국어·영어·사회 세트에서 생기면 이 사실을 그대로 안내한다.
- **옛 판은 옛 구조 그대로**: 2026-09-26 이전에 게시된 판(서술형 3점 × 2 + 논술형 16점, 서술형은 교수 차시 안)은 학생 답안·채점이 문항 번호와 3점 만점에 묶여 있어 고쳐 쓰지 않고 그대로 보이고 채점된다. 새 구조로 바꾸려면 세트를 다시 생성·게시하고 새로 배정한다.
- **원장 화면은 A~E 등급만 보여준다**: `level_ref`(7등급 대응 참조열)는 관리자·교사 화면 모두에 나오지만(스펙에서 원장 제한 규정 없음 — task-7-report.md 5번), 학생 성취수준 문장은 A~E 표현이다.
- **린트 메시지는 `lib/` 안 한글 리터럴이다**: `checks.ts`/`notice-lint.ts`의 이슈 문구가 코드에 하드코딩되어 있다(다국어 대응 시 손봐야 함 — task-3-report.md 관행과 동일, task-9 부채로 기록됨).
- **과학 자료 B/D 잔여물**: 과학 세트는 stage 4 fixture에 공유 자료 B·D 사본을 들고 있다(실제 생성에서는 대주제 공유 자료를 그대로 참조하므로 해당 없음 — mock 전용 이슈, task-6-report.md 5번).
- **세계사 세트는 지원 안 함**: 역사 통합 영역(9역01~02)은 세계사로 분류되어 있으나(2026-09-20 확정), 세계사 세트 자체는 이번 5과목 범위 밖이다.
- **고등 성취수준 없음**: `data/reference/levels/`에 고등학교 파일이 없어(스펙 §6.2 "학교급 분기"가 발표 뒤), 고등 코드는 `levelsBlock`이 조용히 건너뛴다.
