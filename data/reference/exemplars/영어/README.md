# WP5-영어 예시 은행 (Exemplar Bank)

AI가 서·논술형/수행 문항을 생성할 때 참고할 실제 영어 문항·루브릭·모범답안 모음. 모든 레코드는 공공누리 대상 교육부·평가원·서울교육청 공개 자료에서 발췌했으며 `source.file`/`source.pages`로 원문을 추적할 수 있다.

## 분포

- **학교급**: 중 19건 / 고 28건
- **유형(kind)**: 서술형 19건 · 논술형 18건 · 수행 10건
- **학년**: 원문에 학년/학년군이 명시된 경우만 기재(중1/2/3, 고1/2/3). 서울시교육청 자료 일부와 성취수준 자료(수행평가-2)는 학년군만 제시되어 `grade: null` 처리.
- **standard_codes 형식**: 2022 개정 중학교 코드(`[9영0X-XX]`)는 지시된 정규식 `\[\d+영\d{2}-\d{2}\]`을 그대로 만족한다. 다만 **고등학교 선택과목 코드**(공통영어1/2 `[10공영1-...]`·`[10공영2-...]`, 영어Ⅱ `[12영Ⅱ...]`, 영어독해와작문 `[12영독...]`, 심화영어작문Ⅱ `[12심작Ⅱ...]`)와 2015 개정 중학교 코드(`영중9234` 형식, `[9영04-05]`형)는 과목·개정연도별 실제 코드 체계가 정규식보다 복잡하여(과목 약자·로마숫자 삽입) 일부가 엄밀한 정규식과 불일치한다. 이는 오탈자가 아니라 원문을 그대로 옮긴 결과이며, 코드가 아예 없거나(2020년 이전 자료) 형식이 다른 경우 임의로 새 코드를 만들지 않고 원문 그대로 두거나 `[]`로 비워 두었다(예: 중학교 수행평가 문항 자료집의 2015 개정 "영중94xx" 코드는 형식이 근본적으로 달라 `standard_codes: []`로 처리하고 unit 필드에만 과제명을 남김).
- **id 접두어**: `eng-agency-*`(사례집), `eng-midguide-*`/`eng-highguide-*`(가이드북), `eng-midperf-*`(중학교 수행평가 자료집), `eng-seoulpractice-*`(서울 실천하기), `eng-seoultool-*`(서울 서논술형 평가도구), `eng-achievement-*`(성취수준). 47개 id 모두 고유함을 스크립트로 검증함.

## 추출 범위에 관한 결정(중요)

7권 중 다수(특히 `서논술형 평가 도구 개발의 방법과 사례-영어`, `중고등학교 영어과 서·논술형 평가도구 자료집`, `[중학교 영어] 수행평가 문항 자료집`)는 한 "사례/단원"이 여러 개의 연계 문항(문항1~4)과 방대한 교수학습 활동안·형성평가·피드백 사례를 함께 싣고 있다. 실제 AI 예시로 가치가 높은 것은 (a) 완결된 지필/수행 문항, (b) 그 채점 기준, (c) 실제 학생 답안 예시이므로:
- 각 사례·단원에서 **문항 단위**로 분리해 레코드화했다(문항 하나 = 레코드 하나).
- `중고등학교 영어과 서·논술형 평가도구 자료집`(12개 단원, 단원당 3문항 = 36문항 존재)은 지면 관계상 각 단원의 **최종/논술형 문항(대개 문항3)** 위주로 12건만 추출했다. 문항1·2(형성평가 성격의 단답·서술형 도입 문항)는 생략했다.
- `[중학교 영어] 수행평가 문항 자료집`은 11개 문항 중 **쓰기 산출물이 뚜렷한 7개**(동화 인물카드, 학교행사 소감문, leaflet 제작, 신청곡 사연, SNS 캠페인, 팝송 패러디, 미래직업 일기)만 추출했고, 순수 구술·역할극 중심 문항(건강 설문 발표, Reader's Theater, 여행지 소개, 고민 상담 역할극)은 제외했다.
- `(중등)2022 개정 교육과정에 따른 성취수준(영어)`은 지필평가 3종 중 선다형 2종과 수행평가 1종(순수 구술) 제외, 서논술형 1종 + 프로젝트형 수행 1종만 포함했다.

이 선택 기준에 따라 중복(동일 지문·동일 채점기준 반복)은 배제했고, 서로 다른 소재·장르·학년의 문항을 고르게 포함하려 했다.

## 5가지 관찰 (프롬프트 설계 시 참고)

1. **과제 유형이 "통합형"에 수렴한다.** 순수 문법 문항은 거의 없고, 거의 모든 문항이 읽기 지문(또는 표·그래프·인포그래픽)을 먼저 제시한 뒤 요약·설명·비교·의견 제시 등 쓰기 과제로 연결하는 "읽기+쓰기 통합형" 구조다(`eng-agency-001~016`, `eng-seoultool-*` 전부). 프롬프트도 "지문/자료 제시 → 세부 과제" 2단 구조를 기본값으로 삼는 것이 자연스럽다.
2. **분량 제한이 단어 수(word count)로 걸리는 경우가 압도적으로 많다.** "25단어 이상", "60~80단어", "100~120단어" 등 정확한 단어 수 구간이 조건에 명시되고, 채점 기준에도 단어 수 구간별 점수(예: 100~120→3점, 80~100→2점, 40~80→1점)가 따로 배정된다(`eng-seoultool-004`, `eng-seoulpractice-004`, `eng-midguide-002`). 한국어 서논술형의 "문장 수" 제한과 달리 영어는 "단어 수"가 기본 단위이므로, 생성 시에도 분량 조건은 단어 수로 표현해야 한다.
3. **루브릭이 거의 예외 없이 "내용/구성/언어사용(어휘·어법)" 3분류의 분석적 채점**을 취하며, 여기에 과제별로 "과제완성(조건 충족)"이 별도 항목으로 추가되는 4분류 구조가 흔하다(`eng-agency-004`, `eng-midguide-002`, `eng-seoultool-001~012`). "언어사용"은 문법/철자 오류 개수 구간(예: 1개 이하=5점, 2~3개=4점 …)으로 세분화되는 경우가 많아, 정성적 서술보다 정량적 오류 개수 기준이 더 흔하다.
4. **한국어와 영어 사용 경계가 뚜렷하다.** 지시문(발문)·조건·채점기준·피드백은 전부 한국어로 작성되고, 학생이 산출해야 하는 답안(빈칸·문장·문단)만 영어로 요구된다(`stem`에 혼용 표기됨). 단, 세부정보 파악형 문항 일부는 "우리말로 서술하시오"라는 조건으로 답안을 한국어로 요구하기도 한다(`eng-highguide-002`). 프롬프트 생성 시 "지시문은 한국어, 답안은 영어"가 기본값이되 예외를 허용해야 한다.
5. **모범답안이 단일 정답이 아니라 "상/중/하 성취수준별 예시"와 "실제 학생 오답 사례 + 오류 진단형 피드백"으로 함께 제공된다.** 만점 예시뿐 아니라 전형적인 오류가 포함된 부분점수 예시(관사 누락, 3인칭 단수 누락, 어순 오류, 단어 그대로 나열 등)를 나란히 제시하고, 피드백도 "잘한 점 먼저 언급 → 구체적 오류 지적 → 학습법 제안" 순서를 따르는 경우가 많다(`eng-agency-001~012`의 "학생 개별 피드백 예시"). 이는 `exemplar_answers`에 "만점"뿐 아니라 "부분/하" 수준 답안도 함께 담고, `feedback` 필드에 오류 유형과 개선 방향을 구체적으로 적어야 함을 시사한다.

## 불용/제외 처리

- 원문에 등장하지만 서·논술형/쓰기 산출물이 아닌 문항(선다형 지필평가, 순수 구술 인터뷰형 수행평가)은 포함하지 않았다.
- 2015 개정 교육과정 코드(`영중9234`, `영중9441-1` 등, `[중학교 영어] 수행평가 문항 자료집`에서 사용)는 2022 개정 성취기준 코드 형식과 근본적으로 달라 `standard_codes: []`로 비워 두고, 대신 `unit` 필드에 과제명과 언어 형식을 명시했다(코드를 임의로 변환·발명하지 않음).
- 수치가 누락되거나(예: 문항별 배점이 개별 명시되지 않은 경우) 특정 필드에 해당 정보가 없는 경우 `null` 또는 `[]`로 두었고 추정치를 만들어 넣지 않았다(예: `exemplar_answers: []`, `time_min: null`, `points: null`).
