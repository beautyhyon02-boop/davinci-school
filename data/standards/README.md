## 추출 방법

`scripts/extract_standards.py` (pdfplumber로 텍스트 레이어 추출 후 정규식 파싱)를
아래와 같이 실행했다.

```bash
S="C:/Users/beaut/OneDrive/바탕 화면/서논술형"
python scripts/extract_standards.py "$S/[별책5] 국어과 교육과정.pdf" 국어 data/standards/국어.json
python scripts/extract_standards.py "$S/[별책7] 사회과 교육과정.pdf" 사회 data/standards/사회_raw.json  # 아래 설명대로 사회/한국사 두 파일로 나눔
python scripts/extract_standards.py "$S/[별책9] 과학과 교육과정.pdf" 과학 data/standards/과학.json
python scripts/extract_standards.py "$S/[별책14] 영어과 교육과정.pdf" 영어 data/standards/영어.json
```

사회과 별책은 코드 안의 한글 라벨(`역`, `한사`, `한국사` 포함 여부)로
`subject_for_code()`가 성취기준을 사회/한국사로 재분류하며, 추출 스크립트가
그 결과를 그대로 JSON에 기록한다. `사회_raw.json`은 이후 `subject` 필드
기준으로 `사회.json`/`한국사.json` 두 파일로 나누고 삭제했다.

수학과는 단독 별책(별책8)이 없어서, `scripts/extract_math.py`가
`[별책2] 초등학교 교육과정.pdf`/`[별책3] 중학교 교육과정.pdf`/
`[별책4] 고등학교 교육과정.pdf`(학교급별로 모든 교과의 성취기준을 모아 둔
총괄 별책, 별책4는 22MB) 전체를 `extract_standards.parse_standards()`로
파싱한 뒤 코드 라벨(`수`, `공수`, `대수`, `확통`, `기하`, `경수`, `인수`,
`직수`, `수과`, `수문`, `미적Ⅰ`, `미적Ⅱ` 등)이 수학과인 행만 걸러
`data/standards/수학.json`으로 저장한다.

```bash
python scripts/extract_math.py
```

파싱한 각 별책의 페이지 전체 텍스트는 `.superpowers/raw/`(git 추적 제외)에
캐시해 두고 있어서, 재실행해도 22MB짜리 별책4를 다시 pdfplumber로 여는
데 걸리는 몇 분을 매번 기다리지 않는다.

## domain 필드

`(1) 듣기⋅말하기`처럼 짧은 영역 소제목이 성취기준 코드 앞에 바로 나오는
구간(초·중학교, 고등학교 공통국어/공통영어/통합사회/통합과학 등)에서는
`domain`을 자동으로 채웠다. 다만:

- 고등학교 선택과목처럼 영역 소제목 없이 곧장 성취기준이 나오는 구간은
  `domain`을 빈 문자열로 둔다(과정이 바뀌었는데 새 영역 제목을 못 찾으면
  직전 과정의 domain을 이어붙이지 않고 비운다 — 잘못된 값을 남기는 것보다
  비워두는 쪽을 택했다).
- "(1) 교수·학습 방향", "(3) 평가 방법"처럼 실제 내용 영역이 아닌 행정
  소제목은 `domain` 후보에서 제외했다.
- 2주차에 필요하면 과목별 화이트리스트 방식으로 더 정교하게 보강할 수 있다.

## 알려진 문제 / 한계

- `domain`이 비어 있는 행이 있다(위 설명 참고). DB나 화면에서 domain이
  필요하면 2주차에 보강한다.
- pdfplumber의 텍스트 추출은 표(그림/도식 안의 텍스트)를 완전히 배제하지
  못할 수 있다. 성취기준 코드가 있는 줄만 파싱 대상으로 삼고, 표 형태로
  삽입된 참고 자료는 코드 형식(`[숫자+한글+숫자]`)이 아니므로 대부분
  자연스럽게 걸러진다. 다만 육안 검수에서 이상 항목을 발견하면
  `scripts/extract_standards.py`의 `STOP`/`NOISE` 패턴을 보강해야 한다.
- 육안 검수 중 발견해 고친 것들(관련 pytest 케이스도 추가함):
  - 페이지 경계에서 성취기준 문장이 줄바꿈되며 쪽 번호/러닝헤드가 끼어드는
    문제 → 페이지별이 아니라 전체 텍스트를 이어붙여 파싱하고, "OOO
    교육과정"류 러닝헤드와 낱개 대시(-)/불릿 기호만 있는 줄을 잡음으로
    처리하도록 보강했다.
  - 과학과는 성취기준 뒤에 "<탐구 활동>" 같은 꺾쇠 소제목과 예시 활동을
    바로 붙여두는데, 이것이 성취기준 문장에 섞여 들어가는 문제 →
    "<...>" 형태의 줄도 성취기준 해설과 같은 종결 신호로 처리했다.
  - 고등학교 선택과목처럼 영역 소제목 없이 새 과목으로 넘어가는 경우,
    직전 과목의 domain이 잘못 이어붙는 문제 → 코드의 과목 라벨이 바뀌면
    새 영역 제목을 만나기 전까지 domain을 비우도록 했다.
- 수학과(별책8)는 폴더에 파일이 없어, 학교급별 총괄 별책(별책2/3/4)에서
  수학 코드만 걸러 추출한다(위 "추출 방법" 참고). 총괄 별책은 과목별
  별책과 레이아웃이 달라 아래와 같은 문제가 있었고, 모두
  `scripts/extract_standards.py`/`scripts/extract_math.py`에서 고치고
  `tests/extract_standards_test.py`·`tests/extract_math_test.py`에 실제
  관측 문자열 그대로 회귀 테스트를 추가했다:
  - 성취기준 바로 뒤에 다음 소단원명이 "글머리 기호(U+F000) + 소단원명"
    형태로 붙어 나옴(예: "구할 수 있다.  도수분포표와 상대도수") →
    U+F000으로 시작하는 줄은 소제목으로 보고 누적을 멈추도록 STOP 패턴에
    추가.
  - 페이지가 바뀌는 자리에 "쪽 번호" 다음 줄에 과목명만 있는 러닝헤드가
    따로 나옴(예: "234" 다음 줄에 "수학") → 현재 과목명과 완전히 같은
    한 줄은 잡음으로 처리.
  - 고등학교 수학(대수/미적분/경제 수학 등)은 "미적분Ⅰ/Ⅱ"처럼 코드
    라벨에 로마 숫자(Ⅰ·Ⅱ)를 쓰는데, 코드 정규식이 한글만 허용해 코드
    자체를 인식하지 못해 43개 성취기준이 통째로 사라져 있었다 → 라벨
    문자 클래스에 Ⅰ·Ⅱ 추가.
  - 고등학교 수학 성취기준 문장 안 수식 변수·기호(x, y, =, +, a, b, c,
    d, √, 2, n)가 폰트 문제로 유니코드 사용자 영역(PUA) 문자로 추출됨 →
    "[별책4] 고등학교 교육과정.pdf" 실제 페이지(471/473/506/576쪽)를
    pdfplumber로 렌더링해 눈으로 대조 확인한 값으로 치환하는 표
    (`extract_standards.MATH_PUA_GLYPHS`)를 추가했다.
  - 분수식·근호식처럼 2차원으로 쌓인 수식은 pdfplumber의 읽기 순서가
    뒤엉켜, 분자 부분이 코드 표시보다 앞선 줄에 나타나 바로 앞 성취기준
    (이미 "~다."로 끝난 문장) 뒤에 잘못 붙는다. 이미 끝난 문장 뒤에
    한글 없이 기호만 남은 꼬리는 잘라내도록 했고(`_TRAILING_SYMBOL_JUNK`),
    `[10공수2-03-04]`(유리함수)·`[10공수2-03-05]`(무리함수) 두 건은
    잘려나간 분자 정보를 정규식만으로 복원할 수 없어 473쪽을 직접 렌더링해
    확인한 원문 그대로 `scripts/extract_math.py`의
    `FORMULA_FIXUPS`에서 명시적으로 보정했다(추측이 아니라 원문 이미지
    대조 결과 — `.superpowers/pages/`에 렌더링한 페이지 이미지를 보관).
  - 위 수정 후에도 U+E06D(분수선/근호 위 가로줄) 자체는 문맥에 따라
    의미가 달라지는 순수 도형 요소라 특정 문자로 옮기지 않고 위 두 건의
    보정문에서 형태소 그대로("(ax+b)/(cx+d)", "√(ax+b)+c") 반영했다.
- 무작위 10행(초 3·중 2·고 5)을 pdfplumber로 해당 페이지를 직접 렌더링해
  대조한 결과 모두 정확히 일치했다(코드/문장/영역 모두 일치, 2026-09-19).
